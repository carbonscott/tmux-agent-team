The sandbox stays team-wide, because the monitor alone lets one unwalled agent reach everyone's board, main and harness.

Findings

  1. Duplicated JSON keys silently widened a profile. {"web": false, "web": true} resolved to web on, because Python's json keeps the last key. Found by the audit (H8) and now refused by load_cfg(). template/harness/profiles.py
  2. A non-object agent_profiles fell back to the team default. With profile: open, "agent_profiles": ["h1"] left h1 on open. Found by the audit (H11); such a map now grants nothing. template/harness/profiles.py
  3. Three smaller fail-closed gaps. A custom name with a trailing newline (H7), a 3,000-deep chain of bases that gave a traceback (H9), and a custom profile named custom or invalid (H10). All closed.
  4. Behaviour change in an older test. If remote is set and the sandbox is turned back on after setup, the profile no longer resolves. The monitor then refuses every tool. Before this change it paused the team on ssh. Both fail closed, but there is no pause, so the boss is not alerted. tests/team/test_remote.sh now expects the refusal. Two other old tests changed only their message wording.
  5. Work directories inside Claude Code's temp folder lose the write wall. This is not about knobs, and it exists without this change. A work dir under /tmp/claude-<uid>/ let selftest step 3 write outside the workspace, because the sandbox leaves that folder writable. The same profile under the home folder was refused. Follow-up: setup.sh could refuse such a path.
