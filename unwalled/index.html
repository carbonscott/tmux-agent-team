Findings

  1. selftest.sh reported a false FAIL on an unwalled run (fixed). Its last step asks the agent to run a command with the Bash tool's allowed_domains parameter and expects a pause. With the sandbox off Claude Code offers no such parameter, so the agent ran the command plainly and, on the remote profile, got 200. The step is now SKIP in an unwalled run, with the reason; a test covers it. template/harness/selftest.sh:107
  2. Briefs said "There is no network" in an unwalled run (fixed). The Sandbox limit in docs/helper.md and docs/lead.md was rendered unchanged, so every agent was told something false, and the remote agent was told both "never run ssh" and, below, that it may. render.py now adds a "This run is unwalled" section that keeps the rules and drops the claim. template/harness/render.py:65
  3. In an unwalled run, only six commands are gated by profile. The monitor passes ssh, scp, sftp, rsync, curl and wget only for remote. Any other program can open a connection in any profile once the sandbox is off: the bridge CLI, python3 -c urllib…. references/design.md says so ("any program can still open a connection"). Not exercised live for a non-remote agent; read from hook.py. template/harness/hook.py:53
  4. Claude Code's memory feature trips the monitor. In the development run, w1 tried to write a memory file under ~/.claude/projects/…/memory 38 s after the run completed. The monitor blocked it and paused the finished team. Not caused by this branch, and correct (it is outside the workspace), but an unwalled run relies on exactly that rule. template/harness/hook.py:148

Not covered

  • ssh, scp, sftp, rsync and wget to a real remote host, live. Only curl and the bridge were run live; the monitor's handling of the others is covered by tests/accept/remote.sh and tests/team/test_remote.sh with stubs. No direct SSH login was made, to stay inside S3DF's login-rate rule.
  • A crash and launch.sh --resume of an unwalled run (stub tests only).
  • A non-remote agent reaching the network with a program the monitor does not name (finding 3).
  • macOS.
