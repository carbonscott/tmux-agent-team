Findings

  1. 1. The pre-launch probe that goal.md asks for cannot pass on a task made by from-goal.py. --apply removes task.attempted_if. Without it, the merge job rejects a merge only when it breaks a statement that is already done. So test_gateway.sh's wrong answer is ACCEPTED ("checked: nothing attempted yet"), and the right answer then conflicts with it on main: 13 passed, 2 failed. This happened in (a) and in both boss attempts. from-goal.py's own note and goal.md tell the user to make task/probe a right and a wrong answer "or delete them". The first can never pass. I deleted the probe (SKIP). The boss re-added attempted_if: kit/{name}.py, which works only because these statement names map to files. Fixes: from-goal.py keeps or derives attempted_if when it can, or test_gateway.sh checks that a wrong answer does not count instead of expecting a rejection. template/harness/from-goal.py:145, template/harness/gateway.py:353-362, template/harness/test_gateway.sh:44-48, references/goal.md:50-52
  2. 2. "checked: nothing attempted yet" is wrong without attempted_if. Every statement was checked, and roman failed. The merge job's message says nothing was attempted, which hides the failed check from whoever sent it. template/harness/gateway.py:362
  3. 3. --apply silently replaces the task's descriptive STATEMENTS.md, and a team built a different program because of it. The example's 72-line spec became the contract's item text plus Check: lines, with no backup and no warning. The boss's team in attempt 2 then built final without stripping lines (run("rle aab ") gives ['2a1b3 ']; the spec says each line is stripped) and a calc that refuses exponents above 10000. The frozen tests catch neither, so verify.py says 7 of 7. The boss found both itself. I confirmed them on the archived main, and (a)'s and the stall page's teams do not have them. Fix: keep the seed's STATEMENTS.md (for example as SPEC.md), or warn. template/harness/from-goal.py:148-151
  4. 4. boss.sh status exits 1 whenever the team is not paused. The status branch ends with [ -e state/HALT ] && {...}, so a healthy run returns 1. Both boss attempts saw their launch command marked "1 failed" for this reason. template/harness/boss.sh:17
  5. 5. Docs: goal.md's "Not yet shown" is out of date, and the default archive folder can break a contract's guardrails. "no boss has run under /goal" is now shown (attempt 2). The boss noticed this too. teardown.sh --archive defaults to the work directory's parent, and archive.py refuses a folder inside the work directory. With a guardrail that allows only the work directory and .goal/, the boss had to archive into .goal/. references/goal.md:140-142, template/teardown.sh:12, template/harness/archive.py:57
  6. Observation: a safety classifier, not the harness, ended attempt 1. Attempt 1 was stopped twice by Opus 5.5's safeguards. The first stop was non-fatal ("continuing once"). The second refused the request ([reasoning_extraction]), and /goal paused waiting for a user message. Attempt 2 hit one non-fatal stop. Not verified: one possible trigger is the make-goal contract asking the runner to print a ledger entry with a "thought" field every turn.
  7. What references/goal.md says vs what happened Matched: from-goal plan and apply (§1). The evaluator took verify.py's "check:" and PASS lines as the proof of each item (§2, goal.md:69); it quoted them. The boss proved nothing in a workspace (§2). No coaching, no second run (§4). The claims file was built from merges and verify output (§3). Did not match: the probe step (finding 1); "the boss uses no subagents" (§3), since it used checker subagents in turns 2-3; and "one iteration is one wait-run cycle" (§3). The team finished inside turn 1, and the contract's floor of 3 iterations forced two more turns, 13 minutes of checking. Not exercised: a pause under /goal (§4), the time bound (§4), and an agent on the open profile running /goal itself. references/goal.md
